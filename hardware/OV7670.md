# OV7670 camera module

**Status: not yet brought up.** The dashboard reports
`OV7670 OFFLINE — No valid camera frames received`, which is the truthful state.
Nothing below has been verified on hardware yet.

---

## What this module is, and why it is not a webcam

The OV7670 is a raw **parallel DVP** image sensor: an 8-bit pixel bus plus
PCLK / VSYNC / HREF, configured over **SCCB** (an I²C-like bus), and it needs an
external **MCLK** to run at all.

It is **not** a UVC device. It never appears as `/dev/video*`. That means:

- Arduino App Lab's video bricks (`Detect Objects on Camera`, etc.) **cannot**
  drive it. Those expect a Linux video source, typically USB.
- Capture must go through the STM32U585's camera peripheral (DCMI/PSSI) with
  DMA into a frame buffer, configured in Zephyr.

Do not spend demo time trying to make App Lab's USB camera path see this part.

## Wiring, as supplied by the operator

**Unverified against the installed core's pinout.** Check every line before
driving any pin. Do not remap casually.

| OV7670 | UNO Q JMISC | STM32 pin | Function |
|---|---|---|---|
| 3.3V | 53 or 55 | — | power, **3.3 V only** |
| GND | 27 | — | ground |
| D0 | 1 | PC6 | data |
| D1 | 3 | PC7 | data |
| D2 | 5 | PC8 | data |
| D3 | 7 | PC9 | data |
| D4 | 9 | PE4 | data |
| D5 | 11 | PI4 | data |
| D6 | 13 | PI6 | data |
| D7 | 15 | PI7 | data |
| PCLK | 17 | PD9 | pixel clock |
| VS | 19 | PI5 | vertical sync |
| HS | 21 | PD8 | horizontal ref |
| MCLK | 23 | PA8 / MCO | master clock in |
| SCL | 16 | PF14 | I2C4 SCL (SCCB) |
| SDA | 18 | PF15 | I2C4 SDA (SCCB) |
| RST | 25 | PA10 | reset |
| PWDN | 2 | PD2 | power down |

**Electrical rules**

- The OV7670 logic is **3.3 V**. Never feed it 5 V.
- MCLK must be running before the sensor will answer on SCCB at all. A module
  that looks "dead" is usually a module with no clock.
- Keep the parallel data lines short. This is a fast bus on jumper wires.

## Bring-up order

Do these in order. Do not skip ahead; each step is cheap and each one rules out
a whole class of failure.

### Stage A — SCCB identity

Prove the module answers before anything else.

- 7-bit address commonly `0x21` (write `0x42`, read `0x43`)
- Read `PID` (`0x0A`) and `VER` (`0x0B`)
- Expect **`0x76` / `0x73`**

If this fails, the problem is power, MCLK, or wiring — not software.

Dashboard shows: `OV7670 DETECTED` with the id, or stays `OV7670 OFFLINE`.

### Stage B — MCLK

Confirm a clock is actually present and in range (the OV7670 wants roughly
10–24 MHz). Without it, Stage A cannot pass either.

### Stage C — one frame

- **QVGA 320×240, RGB565.** Do not start at VGA; the bandwidth will not survive
  jumper wires.
- Capture exactly one frame and validate it: expected byte count, non-zero
  content, and sane sync behaviour.
- A frame of all zeros is a failure, not a dark room.

### Stage D — live stream

Frame buffer → board endpoint → dashboard. The UI already has the tab and reads
`camera.frame_age_s`, so a stalled stream shows as stale rather than as a frozen
still presented as live.

### Stage E — detection

Only after a stable feed exists. If it does not fit in the time available, keep
the live feed and label vision as unavailable. **A real feed beats fake
detections.**

## What the dashboard expects

The board should add a `camera` object to `GET /api/state`:

```json
{
  "camera": {
    "state": "absent | detected | streaming | error",
    "sensor_id": "0x76/0x73",
    "width": 320,
    "height": 240,
    "fps": 12.4,
    "frame_age_s": 0.08,
    "detail": "human-readable status"
  }
}
```

`fps` and `frame_age_s` must be **measured**, not nominal. The dashboard shows
frame age specifically so a dead camera cannot masquerade as a live one.

Frames are served from `/api/unoq/frame` (proxy route still to be added when
Stage D lands).

## Honesty rules for this panel

- No detection claim without a demonstrated detection.
- Detection confidence is **not** model accuracy. Never print an accuracy figure.
- Absence of detections does not prove the area is empty or the camera is alive.
- Never freeze the last frame and present it as live.
